# Кондитерка

Личная кондитерская книга: рецепты, библиотека компонентов, пересчёт ингредиентов, покупки и дневник разработки десертов. Интерфейс на русском языке, адаптация для компьютера и телефона, установка как PWA.

[Открыть опубликованное приложение](https://konditerka-carnet.primebrook2.chatgpt.site)

**Этот репозиторий содержит самостоятельную серверную версию приложения.** GitHub хранит исходный код и выполняет проверки. Для постоянной работы базы, входа и фотографий нужен запущенный сервер с диском. GitHub Pages подходит только для статических файлов и не может запустить эту серверную часть.

## Что работает

- Рецепты и компоненты: создание, редактирование, копирование, удаление с подтверждением, фотографии, избранное, поиск и фильтры.
- Снимки компонентов с номером версии: изменение библиотечного компонента не переписывает сохранённые десерты.
- Пропорциональный пересчёт всех компонентов с сохранением исходных количеств, в том числе дробных; время и температура не пересчитываются.
- Несколько списков покупок, добавление из рецептов, объединение совместимых единиц (г/кг и мл/л), отметки и вычитание количества «уже есть».
- Лаборатория: идеи, история тестов со снимками рецептур, утверждение готового рецепта.
- Режим приготовления, галереи, импорт текста и текстовых PDF с предварительной проверкой, PDF-экспорт и печать, JSON-копии коллекции.
- Авторизация одного владельца по почте и паролю, смена пароля, серверные сеансы, постоянная SQLite-база и закрытая выдача фотографий.

OCR фотографий и сканированных PDF не подключён: интерфейс сообщает об этом. Приложению нужен интернет для облачной версии; PWA не обещает автономное редактирование. Синхронизация самостоятельной версии выполняется через один сервер: при открытии и возвращении во вкладку данные загружаются повторно. Конфликтующие изменения не перезаписываются молча.

## Запуск на своём компьютере

Нужен **Node.js 24** и **pnpm 11.25.0**.

```sh
git clone https://github.com/milka2025/konditerka.git
cd konditerka
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
cp .env.example .env
```

Откройте `.env` и задайте свою почту и уникальный пароль из 12 или более символов. Пример из `.env.example` намеренно не подходит для входа. Файл `.env` нельзя загружать в GitHub.

```sh
pnpm run build
pnpm start
```

Откройте `http://localhost:3000`. Вход — с почтой и паролем из `.env`. При первом запуске создаётся единственный владелец. Дальше пароль хранится в базе в виде хеша; изменение `.env` не сбрасывает существующий пароль. Сменить его можно в настройках приложения. Публичной регистрации нет.

В `.env` по умолчанию `HOST=0.0.0.0`: для доступа только с этого компьютера укажите `HOST=127.0.0.1`. Для доступа с телефона используйте адрес компьютера и одну сеть. Для работы из интернета настройте HTTPS, как описано ниже.

## Запуск через Docker

После заполнения `.env`:

```sh
docker compose up -d --build
```

Откройте `http://localhost:3000`. База и фотографии сохраняются в постоянном томе `konditerka-data`. Обычный перезапуск контейнера их не удаляет. Команда `docker compose down -v` удаляет том вместе с данными — не используйте её для обычной остановки.

## Размещение в интернете

Разверните Docker-образ на сервере с постоянным диском. Подключите домен и HTTPS через обратный прокси (например, Caddy). Укажите:

- `OWNER_EMAIL` и `OWNER_PASSWORD` — только для первого создания владельца;
- `APP_ORIGIN=https://ваш-домен` — точный адрес без завершающего слеша;
- `NODE_ENV=production`;
- `DATA_DIR=/data`, с постоянным томом в `/data`;
- `HOST=0.0.0.0` и `PORT=3000`.

Для Docker Compose задайте `APP_ORIGIN` в `.env` и проксируйте HTTPS-домен на локальный порт 3000. Без постоянного диска контейнерные платформы могут потерять данные при повторном развёртывании. Репозиторий не создаёт платный хостинг автоматически.

При HTTPS сеансовая cookie имеет `Secure`, `HttpOnly` и `SameSite=Strict`; изменения через API проверяют источник запроса. В базе хранятся хеши пароля и сеансов. Без входа рецепты и фотографии недоступны. Секреты не встроены в браузерный код.

## Резервные копии и перенос данных

В настройках доступен JSON-экспорт и восстановление копий записей. JSON содержит ссылки на фото: это не полный перенос медиа между разными серверами. Для полной резервной копии остановите сервер и скопируйте весь `DATA_DIR` (SQLite-база, сопутствующие файлы и папка `photos`), затем запустите сервер снова. Храните резервную копию вне репозитория.

Опубликованная версия по ссылке выше хранит данные в Sites D1/R2 и использует вход ChatGPT. Самостоятельная версия из GitHub имеет отдельную базу и вход по почте и паролю. Личные данные автоматически не переносятся; экспорт/импорт JSON переносит записи, а фотографии следует переносить отдельно. В открытый репозиторий не включены личные рецепты, база, фотографии владельца, пароль или ключи Sites.

## Проверки

```sh
pnpm run check
pnpm run build
pnpm test
```

GitHub Actions запускает те же проверки. Тесты проверяют расчёты, вход и выход, защиту от конфликтов, работу рецептов/компонентов/покупок/лаборатории, фотографии и сохранение после перезапуска сервера. Они создают отдельную временную базу и удаляют её после выполнения.

## Файлы проекта

- `kitchen.tsx`, `globals.css` — интерфейс;
- `domain.ts`, `validation.ts` — модели, расчёты, импорт текста и проверка данных;
- `pdf.ts` — импорт текстовых PDF и экспорт;
- `server.mjs` — авторизация, API, SQLite, фотографии и выдача собранного приложения;
- `Dockerfile`, `compose.yaml` — запуск с постоянным хранилищем;
- `.github/workflows/check.yml` — автоматические проверки.
